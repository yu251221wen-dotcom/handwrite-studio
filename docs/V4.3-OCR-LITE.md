# V4.3 OCR Lite 与稳定工作流

## 输入边界与隐私

OCR Lite 只处理清晰、基本水平、无明显透视的 PNG、JPG/JPEG 和扫描 PDF。它不实现倾斜校正、四角透视、复杂多栏重建、手写字 OCR 或医学内容自动纠错。用户图片、PDF 和识别文字均留在浏览器；应用从同源静态资源加载 Tesseract worker、WASM、简体中文模型及 PDF.js worker，不把图片发送到第三方 OCR 服务。

`scripts/prepare-ocr-assets.mjs` 在开发和构建前从锁定依赖复制运行资源到 `public/ocr/`。生成目录不提交 Git，但可由完整依赖安装确定性重建。

## 识别与校对链路

```text
PNG / JPG / 扫描 PDF
  -> 浏览器解码 / PDF.js 逐页渲染
  -> Tesseract.js 简体中文识别
  -> OcrDraft（原文、逐行置信度、建议类型）
  -> 用户校对与确认
  -> DocumentBlock[]
  -> V4 Block-aware layout
  -> coverage / Canvas / PNG / JPG / PDF
```

识别阶段只建议 `Heading / Paragraph / List / KeyValue`。无法可靠判断的内容降级为 Paragraph，不会删除数字、日期、剂量、检验值或专有名词。确认导入后，每行保存稳定 `blockId`、`sourceOrder`、`sourceStart`、`sourceEnd` 和 `sourceText`，因此继续受 `Missing = 0` 约束。OCR 不直接写 Canvas。

扫描 PDF 按页渲染和识别；每页完成后立即清空临时 Canvas 并执行 PDF page cleanup。成功、失败或取消都会销毁 PDF loading task 和 OCR worker。

## 全页纸张参数预览

`lib/pages/page-settings-sync.ts` 只复制背景、色彩调整、Fit/Cover/Stretch 变换、原生页脚标记和横线坐标系。临时 `pageSettingsPreview` 只用于渲染，不进入自动保存或 JSON；预览期间禁止拖动行。确认时一次性提交全部页面，因而只增加一个 history entry；取消只丢弃临时状态。

`footerMode` 和 `tableLineMode` 本身是项目级状态，天然作用于全部页面，不需要复制到每个 `PageState`。单行 `manualOffset`、Correction、正文、签名局部调整和选择状态不参与同步。

## 流式导出

`lib/export/stream-export.ts` 以单页生产/消费循环驱动导出。编辑器复用一个高 DPI Canvas：绘制一页、编码、下载或上传到匿名 PDF job、释放该页 Blob/Bitmap、把 Canvas 重置为 1×1，再向主线程 yield。PDF 后端按 Session 隔离接收逐页 PNG，完成时用 ReportLab 逐页写入 A4 PDF，并在完成或取消后删除临时 job。

该设计保证 7–10 页的内存随“单页大小”而不是“总页数”增长；取消信号会阻止下一页、清理后端 job 并恢复按钮。600 DPI 不创建整篇 Canvas 集合。

## 表格线与罗马数字

`tableLineMode` 的解析集中在 `lib/handwriting/table-line-style.ts`：

- `auto`：结构化/横线背景不重复画线，纯纸背景使用克制辅助线；
- `hidden`：完全不画程序线，但保留 TableBlock 单元格、列锚和对齐；
- `adaptive`：有纸线时沿用背景结构，纯纸时只画低 alpha 水平线；
- `visible`：绘制完整程序表格线，使用保存的颜色、透明度和线宽。

`lib/handwriting/roman-numerals.ts` 仅对 Roman numeral 单元格字符附加轻微、确定性的比例、旋转、基线和透明度变化。随机 key 使用 document / field / source index / seed，不依赖 pageIndex、x、y 或背景；同一人风格连续，但同页不同出现不会复制粘贴式完全一致。

## 兼容范围

SchemaVersion 保持 3。旧 V3 JSON 通过 normalize 获得 `tableLineMode: auto` 和保守的默认线条样式，既有页面、字符状态、手动偏移、涂改和 Seed 不变。OCR 原始草稿和未确认的全页预览不持久化。
